## 1. 项目背景

游戏内的乐器演奏系统（如《第五人格》的琴师/演奏玩法）允许玩家在自由演奏模式下用键盘或触摸弹奏乐器。人类手动演奏受限于熟练度，而曲谱资源大量以 MIDI、MusicXML、简谱形式存在。目前缺少一个**本地的、跨平台的、以游戏乐器 Profile 为核心的曲谱转换与辅助演奏工具**。

ScoreLeap 将标准音乐输入转换为适合游戏内乐器演奏的时间轴，并通过 Windows 键盘注入或 Android 触摸手势在游戏的自由演奏、个人空间等非竞技场景完成演奏。

**架构约束**：项目不绑定单一游戏。《第五人格》只是第一个 Game Profile（`identity-v`）。项目名称、核心 crate、公共接口中不出现 Identity V 字样。

## 2. 用户痛点

1. **手动演奏门槛高**：游戏内乐器需要记住键位与节奏，复杂曲目难以手弹。
2. **曲谱转换麻烦**：网上找到的 MIDI/简谱不能直接用于游戏乐器，需要人工转调、裁剪音域、简化和弦。
3. **工具碎片化**：现有工具多绑定单一游戏、单一平台（多为 Windows 脚本），无跨平台方案，且安全性不可控。
4. **隐私担忧**：用户不希望把自己的 MIDI/音频上传到不信任的在线服务。
5. **安全顾虑**：社区流传的注入/内存修改类工具违反游戏条款且有封号风险，用户需要一种透明、可见、可随时停止的替代方案。

## 3. 目标用户

- 游戏内乐器玩法爱好者（自由演奏、个人空间演奏）；
- 会找 MIDI 但不会编曲的普通玩家；
- 想快速试听「这首曲子在我的乐器上能不能弹」的玩家；
- 跨平台玩家（Windows 桌面 + Android 手机双端）；
- 对隐私敏感、不愿上传曲谱的用户。

非目标：专业音乐制作人（需要 DAW 能力）、竞技排位玩家（本工具明确不支持竞技场景）。

## 4. 典型使用场景

1. **Windows 桌面演奏**：玩家下载一首 MIDI → 导入 ScoreLeap → 选择《第五人格》36 键乐器 Profile → 自动转调/折叠/量化 → 打开游戏自由演奏页面 → 三秒倒计时后自动演奏 → 随时暂停/紧急停止。
2. **Android 触屏演奏**：手机端同样导入 MIDI → 校准琴键坐标 → 开启无障碍服务（用户主动授权）→ 在游戏内自动点击琴键演奏，通知栏常驻可停止。
3. **试听预览**：导入后先在钢琴卷帘预览页查看编排后的时间轴（可视化预览，v0.1 无音频播放）、查看当前音符，再决定是否演奏。
4. **参数调整**：手动移调、选择主旋律轨道、调整最大复音，观察预览变化后重放。

## 5. 产品价值

- **本地优先**：所有转换本地执行，不上传用户文件；
- **跨平台**：同一份音乐中间格式（Music IR）+ 平台无关时间轴，双端复用核心逻辑；
- **可配置**：Game Profile 体系使适配新游戏/新乐器只需新增 JSON Profile；
- **安全透明**：不注入、不改内存、不隐藏行为；全流程可见、可停；
- **合规**：面向自由演奏/个人空间场景，明确风险提示，不提供竞技与反检测能力。

## 6. 产品名称与品牌说明

- 中文名：**谱跃**（曲谱 + 跃动/演奏之意）；
- 英文名：**ScoreLeap**；
- 品牌一致性：仓库名 `scoreleap`、Tauri identifier `com.superdaobo.scoreleap`、Android namespace `com.superdaobo.scoreleap`、Rust crates 统一前缀 `scoreleap-*`；
- 命名原则：不得使用 Identity V / 第五人格作为项目名、crate 名或公共接口名；游戏名只出现在 `game-profiles/identity-v/` 的 profile 元数据中。

## 7. 功能范围

### v0.1.0 Windows MIDI MVP（必须）
- 导入 `.mid` / `.midi`；
- MIDI 基础信息读取（格式、轨道数、时长、Tempo Map）；
- 轨道列表与启用/禁用；
- Tempo Map（tempo 变化正确）；
- Note On / Note Off（含 velocity=0 语义、running status）；
- 自动转调、手动移调（±半音）；
- 音域折叠（超出乐器音域的音符折叠/丢弃策略）；
- 最大复音限制（和弦简化）；
- 节奏量化（可选网格）；
- 和弦简化；
- Game Profile 加载（首个 36 键 profile）；
- Windows 按键映射（扫描码）；
- 三秒倒计时、开始、暂停、继续、停止、紧急停止、释放全部按键；
- 播放速度调整；
- 当前进度与当前音符显示；
- 基础钢琴卷帘预览；
- 本地设置、本地日志、错误提示；
- Windows 构建（NSIS 安装包）、自动测试、README。

### 后续版本（概要）
- v0.2.0：Android MIDI MVP（触摸演奏、无障碍、校准）；
- v0.3.0：曲谱编辑器（钢琴卷帘编辑、撤销重做、.scoreleap 文件）；
- v0.4.0：Windows 音频转 MIDI（Basic Pitch ONNX）；
- v0.5.0：Android 本地 AI 与在线转换备选（研究先行）。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 调度精度 | 按键时刻误差目标 ≤ 10ms；核心时间轴整数微秒（i64），禁止模糊浮点秒 |
| 累计漂移 | 连续演奏 3 分钟无明显累计漂移（验收标准） |
| 停止安全 | 暂停/停止/崩溃后不得残留按键；提供全部按键释放 |
| 启动性能 | 应用冷启动 ≤ 3s；MIDI 解析 ≤ 1s（10 万事件以内） | 性能冒烟测试（归 V1-23） |
| 资源占用 | 空闲内存 < 300MB；CPU 仅调度时活跃 | 性能冒烟测试（归 V1-23） |
| 本地优先 | 转换全本地；无遥测默认关闭 |
| 可测试性 | 输入后端可 Mock；Scheduler 支持虚拟时钟 |
| 可移植性 | 核心 crate 不依赖平台 API（除 scheduler 与输入后端） |
| 国际化 | UI 中文优先，代码/文档英文标识符，README 双语 |
| 无障碍 | Android 侧明确解释用途、用户主动开启、通知栏常驻 |

## 12. 游戏 Profile 系统

- 目录：`game-profiles/<game-id>/`，每个 profile 包含：
  - `profile.json`：乐器布局、音域、键数、复音上限、元数据（game 名称、免责声明）；
  - `windows-keymap.json`：音名 → 扫描码映射；
  - `android-layout.json`：琴键坐标布局（归一化坐标，供校准使用）；
- 首个 Profile：`game-profiles/identity-v/`（36 键游戏乐器；音域与键位以公开的游戏内布局为准，不读取游戏内存）；
- 运行时校验：加载时用 serde 校验 schema，失败给出明确错误；
- 未来：`web-piano` 等网页钢琴 Profile。

## 13. Windows 方案

- **输入**：`SendInput` + `KEYEVENTF_SCANCODE`（扫描码而非虚拟键，兼容 DirectInput/原始输入类游戏）；键盘映射来自 profile 的 `windows-keymap.json`。
- **调度**：QPC 为时钟源 + 单线程 deadline 驱动（每次触发后按 QPC 重算绝对到期时间）；`timeBeginPeriod(1)` 会话级使用；高分辨率等待计时器唤醒；误差预期 1–3ms（详见调研归档）。
- **全局快捷键**：tauri-plugin-global-shortcut 2.3.x（已定稿）；默认紧急停止 Ctrl+Alt+F9。
- **窗口策略**：仅在被聚焦窗口为已选游戏窗口（或用户确认的测试窗口）时注入；提供 Windows 测试页面（记事本/文本框）验证按键。
- **紧急停止**：全局快捷键 + UI 按钮 + 窗口失焦自动暂停（可配置）；维护「已按下按键集合」，停止时全部释放；panic hook 与进程退出钩子尽力释放。
- **详细方案**：见 ADR-0005 与 ARCHITECTURE.md。

## 14. Android 方案

- **架构**：Tauri 2 Android 插件（`tauri-plugin-scoreleap-input`），Kotlin 桥接 + Rust mobile.rs。
- **触摸**：AccessibilityService `dispatchGesture`（GestureDescription）；单指 tap + 多指和弦（多点 Path）；用户主动开启且每次使用前确认。
- **服务**：前台通知常驻（含暂停/停止按钮）；进程被杀时手势自然停止（Android 生命周期保证）。
- **坐标**：横屏归一化坐标系统 + 琴键校准界面（用户点击实际琴键位置，保存为 CalibrationProfile）；分辨率/旋转变化处理。
- **合规**：无障碍服务用途如实声明（辅助演奏非无障碍目的——评估 Google Play 政策风险，见 RISK_AND_COMPLIANCE.md），不读取与演奏无关内容。
- **详细方案**：见 ADR-0005 与 ARCHITECTURE.md。

## 15. AI 转录方案

- v0.1 / v0.2：**不引入任何 AI 推理**。
- v0.4（Windows）：音频 → 解码（Symphonia，MPL-2.0）→ 重采样（rubato，22050Hz mono）→ Basic Pitch ONNX 分段推理（官方 nmp.onnx 约 225KB、Apache-2.0 可随包分发；ort crate 自动拉取预编译 ONNX Runtime）→ 音符后处理 → Music IR。
- v0.5（Android）：先研究 ONNX Runtime Mobile 可行性（内存、温度、功耗、分段推理、低端机降级），再做实现决策；同时研究可选在线转换服务（用户明确选择才上传）。
- 约束：模型不得在许可证确认、体积评估、性能测试前进入安装包；模型通过发布资产/应用内下载分发并校验 SHA256，不提交进 Git。

## 16. 隐私策略

- **本地处理为默认**：MIDI、音频、曲谱全部在本地转换，不上传；
- **在线服务为显式选择**：v0.5 若提供在线转换，必须单独勾选同意，且说明传输内容；
- **无障碍数据**：不读取、不收集、不上传与演奏无关的界面内容（密码、聊天等）；
- **遥测**：v0.1 完全无遥测；未来版本默认关闭、开启需用户同意；
- **日志**：本地日志包含用户文件名（可配置关闭），不自动上传；
- **第三方依赖**：引入前审计许可证与数据行为。

## 17. 风险提示

- 使用本工具存在第三方游戏服务条款风险，可能导致账号处罚；必须向用户展示醒目风险提示（首次启动 + 每次演奏前确认）；
- 仅用于自由演奏、个人空间或非竞技场景；
- 本工具不提供、不实现反检测、隐藏自动化、随机化输入规避检测等能力；
- 详见 `RISK_AND_COMPLIANCE.md`。

## 21. 不做什么（明确非目标）

- 不做进程注入、内存读取/修改、DLL/驱动注入、Hook 游戏内部函数、绕过反作弊；
- 不提供隐藏自动化、随机化输入规避检测、自动判断规避时机；
- 不支持竞技/排位场景、角色移动与战斗操作；
- 不自动下载受版权保护的音乐；不提供社区曲库、云同步、在线账号；
- 不实现复杂 DAW 能力；不自动识别游戏琴键坐标（必须人工校准）；
- v0.1 不做：Android 正式演奏、音频转 MIDI、MusicXML、图片识别、后台控制未授权应用。

## 22. 已知技术风险

1. 游戏键盘输入兼容性（DirectInput/原始输入差异）——需实机验证；
2. 调度精度受系统定时器分辨率影响——需精度测量；
3. Android 无障碍手势在游戏内的可用性（SurfaceView/Unity 输入管道）——需实机验证；
4. Android 后台限制/厂商省电策略可能中断服务——前台服务 + 用户引导；
5. 游戏 UI 改版导致琴键坐标失效——校准 Profile 可重新校准；
6. 多点触摸兼容性（部分设备触控采样率/多点支持）——和弦降级策略；
7. 崩溃残留按键——释放机制 + 用户可重启游戏；
8. ONNX 模型体积与移动端性能（v0.4/v0.5）——模型选择与裁剪研究；
9. 应用商店审核（无障碍服务用途）——不上架策略；
10. 版权与 ToS 合规——文档化 + 风险提示。

## 24. MVP 验收标准（v0.1.0）

1. 能导入合法 MIDI；
2. 能解析多轨 MIDI；
3. Tempo 变化正确；
4. 能转换为统一 Music IR；
5. 能生成平台无关 CompiledSequence；
6. 能应用 36 键 Profile；
7. 能在 Windows 测试页面执行按键；
8. 能在目标游戏自由演奏页面进行手动验证；
9. 连续演奏三分钟没有明显累计漂移（量化：三分钟末按键时刻相对计划时刻的累计偏差 ≤ 50ms，单次误差 ≤ 15ms；实机测量归 V1-13 技术验证）；
10. 暂停后没有残留按键；
11. 停止后全部按键被释放；
12. 崩溃或窗口关闭时尽量释放全部按键；
13. 重复音符不会因为错误去重而丢失；
14. 和弦能同时触发；
