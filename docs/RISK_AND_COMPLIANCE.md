# 风险与合规文档 — ScoreLeap（谱跃）

> 本文档分析产品全生命周期的风险与合规边界。所有风险都有缓解措施；「不得实现」项为硬性底线。

## 2. 游戏服务条款风险（R1）

- 游戏运营方通常禁止任何第三方软件干预游戏运行；即使仅在自由演奏模式使用，仍存在条款违反风险，可能造成账号处罚。网易《第五人格》用户协议/游戏规则含「禁止使用外挂、辅助软件、脚本等第三方程序」类条款（行业标准表述），模拟键盘/触摸输入的辅助演奏大概率落入兜底条款，**封号风险确定性高**；不涉及破解/绕过验证/商业牟利时民事与刑事责任风险低。
- 缓解：
  1. 首次启动 + 每次演奏前的双重风险确认；
  2. 文档明示「使用后果由用户自行承担」，宣传口径避免「代打」「竞技优势」表述；
  3. 产品只做键盘/触摸事件注入，不读取/修改游戏进程数据；
  4. 用户可随时紧急停止；
  5. 发布时在 README 与风险提示页附官方协议链接（id5.163.com）供用户自查。
- 依据：网易游戏《用户协议》与《第五人格》官网（id5.163.com）条款（发布前在 README 与风险提示页引用官方链接）。

## 3. 第三方自动化风险（R2）

- 使用自动化输入在任何游戏中都可能被检测系统识别为异常行为。
- 缓解：不实现任何「规避检测」能力（不随机化输入、不隐藏行为、不伪装进程）；产品界面持续显示演奏状态（可见性 = 用户可解释性）；紧急停止机制。
- 产品立场：诚实、可见、可控，替代隐蔽脚本方案。

## 4. Android AccessibilityService 风险（R3）

- Google Play 政策（官方）：**automation tools 不属于 accessibility tools**——「仅以服务残障人士为核心目的」的应用才能声明 isAccessibilityTool；自动化工具必须按「自动化用途」走**应用内显著披露 + 肯定式同意 + Play Console 声明**；**确定性规则脚本允许**（「If Trigger X, perform Action Y」的静态映射），**自主规划/决策严格禁止**；违规可导致应用下架与开发者账号终止。
- 缓解：
  1. 本产品**不上架 Google Play**（GitHub 直发 APK）——规避商店审核面；
  2. 不声明 isAccessibilityTool=true；无障碍服务用途在应用内如实声明（「模拟触摸执行乐谱演奏」），不谎报为无障碍目的；
  3. 注入逻辑保持确定性规则映射（音符→点击），禁止任何自主决策逻辑；
  4. 服务仅实现手势分发，不读取界面节点、不收集任何数据；
  5. 用户必须手动开启服务，每次演奏前再次确认；
  6. 前台通知常驻，可随时停止。
- 技术边界：`dispatchGesture` 注入触摸事件，不需要读取无障碍树；服务不得实现 `onAccessibilityEvent` 数据采集。

## 5. 应用商店审核风险（R4）

- 除无障碍政策外，涉及自动化输入的工具普遍面临商店审核不确定性。
- 缓解：不排期应用商店；以 GitHub Releases 作为唯一分发渠道（v0.1/v0.2）；未来如需上架，单独评估并更新本文档。

## 6. 音乐版权风险（R5）

- 用户导入的 MIDI/音频版权归原权利人所有；MIDI 文件可能包含受保护的编曲表达。
- 缓解：
  1. 工具只处理用户自备文件；
  2. 不提供社区曲库、曲谱搜索、自动下载受版权保护音乐；
  3. 隐私策略明确「文件不上传」；
  4. 文档建议用户仅使用有合法来源的曲谱。

## 7. AI 模型许可证（R6）

- 模型权重与代码许可证可能不同（Basic Pitch 代码 Apache-2.0、ONNX 模型可再分发；piano 权重 CC-BY-4.0 需署名；Demucs MIT——均可再分发，需保留 LICENSE/NOTICE）。
- 缓解：
  1. 每个模型引入前完成许可证审计并记录在 `models/manifest.json` 与本文档；
  2. 许可证不允许再分发的模型 → 改为应用内下载/引导用户自行获取；
  3. 模型不进入 Git 仓库与安装包（发布资产 + SHA256 校验）。

## 8. 第三方代码许可证（R7）

- 项目采用 GPL-3.0；依赖以宽松许可证（MIT/Apache-2.0/MPL-2.0/BSD）为主。
- GPL-3.0 自身义务：随发布物附许可证全文与第三方声明（THIRD_PARTY_NOTICES）；GitHub Release 附源码链接（满足 GPL §6(d) 对应源码义务）；源文件头加版权与许可证指针；Rust 静态链接使依赖传染明确。
- 缓解：
  1. CI 引入 `cargo-deny`（默认拒绝制 + SPDX 白名单：MIT/Apache-2.0/BSD-2-Clause/BSD-3-Clause/ISC/Zlib/CC0-1.0/Unicode-DFS-2016/GPL-3.0/Unlicense/MPL-2.0），`EmbarkStudios/cargo-deny-action@v1`；白名单含 Unlicense（midly，v0.1 核心依赖）与 MPL-2.0（Symphonia，v0.4）——均为可再分发宽松许可；
  2. 前端依赖用 license-checker（--onlyAllow 白名单）审计；
  3. 引入任何 GPL/LGPL 强传染依赖前必须记录并评估；
  4. 生成 THIRD_PARTY_NOTICES 随安装包分发。

## 9. 用户隐私（R8）

- 本地处理为默认：MIDI/音频/曲谱不离开用户设备；
- 无账号体系、无云同步、无遥测（v0.1 完全离线）；
- 未来任何在线功能（v0.5 在线转换备选）必须：用户显式选择 + 单独同意 + 说明传输内容与用途；
- 无障碍数据（若未来实现采集）零容忍：不收集、不上传。

## 10. 本地日志（R9）

- 日志文件位于用户数据目录，默认 info 级别，保留 7 天；
- 默认不记录文件内容，文件名可配置脱敏；
- 日志不自动上传；「导出日志」功能仅在用户主动操作时生成压缩包。

## 11. 崩溃时残留按键（R10）

- 风险：进程崩溃/被杀时，已按下的按键可能未抬起，导致游戏内按键卡住。
- 缓解：
  1. 维护已按下按键集合，正常停止/暂停/紧急停止全部释放；
  2. `panic` hook 与进程退出钩子尽力释放并写日志；
  3. 崩溃后启动时检测上次会话异常退出，提示用户重启游戏以恢复按键状态；
  4. 无法 100% 保证 → 文档明示此限制。

## 12. Android 设备过热和耗电（R11）

- 长时间演奏/未来本地 AI 推理可能导致发热耗电。
- 缓解：演奏会话空闲超时自动停止；v0.5 分段推理 + 低性能设备降级（更小模型/更低帧率）；文档提示建议充电与散热环境。

## 13. Android 后台限制（R12）

- Android 8+ 后台执行限制、厂商激进省电策略可能杀死前台服务或中断无障碍服务。
- 缓解：
  1. 演奏期间使用前台服务（Foreground Service，声明 `foregroundServiceType`）；
  2. 引导用户关闭对该应用的电池优化（文档 + 设置跳转）；
  3. 服务被杀 → 手势自然停止（无残留注入），状态机复位，提示用户。

## 14. 多点触摸兼容性（R13）

- 部分设备触控采样率低或游戏对多点支持有限，和弦手势可能丢点。
- 缓解：校准向导中提供「和弦测试」；失败策略可配（跳过该音符 / 降为单音优先）；实机设备矩阵测试（v0.2）。

## 15. 游戏 UI 改版导致坐标失效（R14）

- 游戏更新可能改变琴键位置，使已校准坐标失效。
- 缓解：CalibrationProfile 记录设备/分辨率/日期；检测到分辨率变化提示重新校准；一键重新校准流程；坐标存归一化值降低版本间失效概率。

## 16. 不得实现的反作弊绕过能力（R15，硬性底线）

**禁止实现**（任何版本、任何形式）：

- 读取游戏进程内存；
- 修改游戏内存；
- DLL 注入；
- 驱动注入；
- Hook 游戏内部函数；
- 绕过反作弊；
- 伪装进程；
- 隐藏自动化行为；
- 随机化输入以规避检测；
- 自动判断何时规避检测；
- 自动竞技操作（排位/匹配/战斗）；
- 角色移动和战斗操作；
- 未经用户确认的后台操作。

**允许范围**（仅此）：

- 用户明确导入曲谱；
- 用户明确选择目标 Profile；
- 用户明确点击开始；
- 按照确定的曲谱时间轴执行；
- 提供可见的播放状态；
- 提供随时停止能力；
- 在自由演奏或非竞技场景使用。
