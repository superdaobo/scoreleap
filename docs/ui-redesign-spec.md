# ScoreLeap 前端界面重设计规格说明

> 本文档供前端设计/开发 AI 使用：先读透「应用定位与核心流程」与「页面规格」，再动手设计。
> 技术栈约束见文末「技术约束」，必须严格遵守，不得更换技术方案。

---

## 一、应用定位

**ScoreLeap（谱跃）** 是一款 Windows 桌面钢琴辅助工具，目标用户是**钢琴/键盘游戏玩家**（如《第五人格》等含钢琴玩法的游戏）。

核心价值链路：

```
导入音乐 → 转成游戏乐器可演奏的谱 → 一键自动演奏（注入游戏按键）
```

两条输入路径：

1. **MIDI 导入**：直接导入 .mid/.midi 文件
2. **音频转录（实验功能）**：选择 MP3/WAV/FLAC（≤200MB、≤10 分钟），本地 ONNX 模型识别钢琴音符 → 生成 MIDI（全程本机处理、不上传）

输出：面向游戏乐器 Profile（如 identity-v 36 键）的**编排序列**，可自动演奏（模拟键盘输入注入游戏）。

**关键特性**：
- 纯本地处理（隐私承诺：文件不上传、不收集遥测）
- 自动演奏涉及游戏自动化，**必须先通过风险确认页**才能使用（合规门槛）
- 支持三档识别预设（均衡/细节/降噪）+ 高级阈值覆盖
- 紧急停止快捷键 Ctrl+Alt+F9（立即释放全部按键）

```
                                  ▼

```

## 三、设计原则与视觉方向

### 3.1 整体气质

- **钢琴 + 舞台**：暗色舞台背景、霓虹渐变（靛蓝→紫罗兰）作主强调色，琥珀色作警告/模型提示色，翠绿作成功/演奏中状态色
- **沉浸优先**：演奏/编排场景是"舞台"，信息页面是"控制台"
- 深色主题（slate-900 系底），层次用边框 + 半透明卡片区分，不用大面积色块
- 圆角（rounded-xl 卡片 / rounded-lg 控件）、克制阴影

### 3.2 现有视觉基线（建议延续或在此基调上优化）

| 用途 | 现有取值 |
|---|---|
| 背景 | `#0b1220`（slate-950 附近）/ `bg-slate-900` |
| 卡片 | `bg-slate-800/40` + `border-slate-800` |
| 主强调 | `from-indigo-500 to-violet-600`（渐变按钮） |
| 文字主/次 | `slate-100` / `slate-400` |
| 成功 | `emerald-400` |
| 警告 | `amber-300/400` |
| 危险 | `red-400/600` |
| 等宽数字 | `font-mono tabular-nums`（BPM、时长、进度） |

### 3.3 设计目标（重新设计时优先）

1. **一眼看懂状态**：转录进度、模型状态、演奏状态用颜色 + 图标 + 文字三重表达
2. **减少操作跳转**：当前"编排"与"演奏"都在编排工作台，重新设计时考虑合并为单一工作台或清晰的两步
3. **空态引导**：每个页面都要有高质量空态（无曲谱/无轨道/未编译/模型未装）
4. **大字号数字与音符可视化**：BPM、音符数、进度是核心信息

## 四、信息架构与导航

### 4.1 导航方案（建议）

**顶部全局导航栏**（当前实现没有全局导航，只有页面内返回链接，是重要改进点）：

```
[♫ ScoreLeap]  [曲谱库] [测试] [设置]        [紧急停止 █]  ← 常驻紧急按钮
```

- 常驻元素：Logo、页面入口（曲谱库/测试/设置）、**紧急停止按钮**（全局可用，红色，演奏中闪烁）
- 子页面（曲谱详情、编排工作台、转录）用面包屑/返回链接，不占主导航
- 紧急停止按钮在"演奏中/暂停中"时高亮并呼吸闪烁

### 4.2 页面路由一览

| 路由 | 页面 | 导航层级 |
|---|---|---|
| `/` | 曲谱库（首页） | 主导航 |
| `/doc/:docId` | 曲谱详情 | 子页 |
| `/arrange/:seqId` | 编排工作台 | 子页 |
| `/transcribe` | 转录工作台（可选新增） | 子页 |
| `/test` | 键位测试 | 主导航 |
| `/settings` | 设置 | 主导航 |
| `/risk` | 风险确认（首启强制） | 独立 |

**元素清单**（若独立成页）：

| 元素 | 说明 |

| 文件选择卡 | 拖拽区 / 「选择音频文件」按钮 + 格式与限制说明 |

## 七、全局状态与反馈设计

### 7.1 模型状态（settingsStore/modelStore）

`unknown → configuration_missing / not_installed → downloading（进度）→ ready / failed / update_available`

各状态在页面中的表现：
- **not_installed / configuration_missing**：首页琥珀提示条 + 设置页主按钮「下载模型」
- **downloading**：进度条 + 「取消下载」
- **failed**：红色错误条 + 「重试下载」
- **update_available**：「确认更新」
- **ready**：绿色徽标，首页不再提示

### 7.2 转录任务状态

`Queued → Starting → ValidatingInput → LoadingModel → Transcribing → WritingMidi → ImportingMidi → Completed / Failed / Cancelled`

阶段文案建议中文友好化（如"正在加载模型""正在识别钢琴音符""正在生成 MIDI"），错误用 `error_code + message` 映射为可读文案。

### 7.3 播放状态

`Idle → Countdown → Playing ⇄ Paused → Stopped / Finished`

- Countdown：琥珀徽标 + 大数字 + "请切换到游戏窗口"提示
- Playing：翠绿徽标 + 进度条 + 卷帘红色位置线
- 紧急停止：全局可用（导航栏常驻按钮 + Ctrl+Alt+F9）

### 7.4 空态设计

| 场景 | 空态内容 |
|---|---|
| 无曲谱 | 🎼 + "将 MIDI 文件拖到这里" + 导入按钮 |
| 曲谱无轨道启用 | 编排侧栏琥珀提示 |

## 八、技术约束（必须遵守）

| 项 | 约束 |
|---|---|
| 框架 | Vue 3（`<script setup>` Composition API）+ TypeScript 严格模式 |
| 构建 | Vite（端口 1420 strictPort）+ `pnpm` 包管理 |
| 样式 | **Tailwind CSS**（沿用现有 slate/indigo/violet 色板；不要引入 UI 组件库） |
| 状态 | Pinia stores（已有：`libraryStore`、`transcriptionStore`、`modelStore`、`playbackStore`、`settingsStore`）——**不得绕过 store 直接调后端** |
| 后端调用 | 统一走 `src/services/api.ts` 的封装函数（Tauri `invoke`），页面不得直接 `invoke` |
| 事件订阅 | 走 `src/services/events.ts`（`transcription://*`、`playback://*`、`model://*`） |
| 类型 | 全部类型在 `src/types/index.ts`（与 Rust 端 snake_case 严格对应；新增类型必须同步） |
| 路由 | `src/router/index.ts`；风险确认守卫：未确认时任何路由重定向到 `/risk` |
| 桌面能力 | Tauri 2（文件选择、进程、快捷键）；音频/模型均在本地 |
| 现有页面文件 | `src/views/`：LibraryPage / DocumentPage / ArrangePage / TestPage / SettingsPage / RiskPage（重设计可重写，但**页面职责与路由不能丢**） |
| 测试 | 前端 vitest：新增/修改 store 逻辑必须补测试（`src/stores/__tests__/`） |
| 版本 | 0.2.4（当前） |
