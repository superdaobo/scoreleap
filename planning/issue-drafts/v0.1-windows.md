## V1-13 完成 Windows SendInput 技术验证

### 背景
SendInput + 扫描码方案需要先验证可行性（H1/H7 假设），再进入正式实现。

### 问题
验证：SendInput 扫描码在 Windows 上注入键盘事件的行为、与记事本/目标游戏的兼容性、E0 扩展扫描码处理、定时精度基线（QPC + timeBeginPeriod）。

### 目标
一份可复现的技术验证报告 + experiments 目录下的最小验证代码（非正式实现）。

### 用户价值
降低正式实现返工风险。

### 范围
- experiments/windows-input/：SendInput 最小注入程序（按下/抬起、扩展码）
- 精度基线：不同休眠策略的抖动测量（std sleep / timeBeginPeriod(1) / 高分辨率等待计时器）
- **三分钟连续演奏漂移测量**：实机长时间注入，记录三分钟末累计偏差（验收标准 9 的量化数据：累计偏差 ≤ 50ms）
- 验证项：记事本输入、游戏内乐器键（人工验证，记录结果）
- 报告写入 docs/（技术验证结论）

### 非目标
正式 Backend 实现（V1-14）、自动窗口检测、Hook 类方案（禁止）。

### 技术建议
- 用 windows crate（版本锁定）；
- 精度测量脚本记录 min/max/avg 抖动；
- 失败不阻塞：结论作为 V1-14 输入。

### 依赖关系
V1-01。

### 验收标准
1. 最小程序可在记事本输入；2. 扩展扫描码行为正确；3. 精度报告产出；4. 三分钟漂移数据产出（累计偏差 ≤ 50ms）；5. 结论文档化并评审。

### 测试要求
无自动化测试（实机验证）；记录人工验证步骤与结果。

### 文档要求
docs/ 技术验证结论；更新 ADR-0005 如有偏差。

### 风险
游戏对输入管道兼容性未知；实机验证需要目标游戏环境。

### 完成定义
报告评审通过 + 结论回填 ADR。

## V1-14 实现 Windows 输入 Backend

### 背景
调度核心（V1-12）需要真实注入后端。

### 问题
`SendInputBackend`：KEYEVENTF_SCANCODE/KEYUP、E0 前缀、按键集合跟踪、release_all、前台窗口检查。

### 目标
desktop.rs 后端 + 测试页可调用 + 单元测试（mock 化边界）。

### 用户价值
真实键盘演奏能力。

### 范围
- `SendInputBackend` 实现 InputBackend trait
- 扫描码解析（含扩展码）
- 前台窗口检查（GetForegroundWindow + 用户确认交互）
- 崩溃兜底钩子（panic hook 调 release_all）

### 非目标
窗口自动识别/匹配、后台注入策略、Hook。

### 技术建议
- 每帧注入前校验前台窗口（用户配置：仅当聚焦目标窗口时注入）；
- 注入失败返回结构化错误 → 触发自动紧急停止。

### 依赖关系
V1-12、V1-13、V1-06。

### 验收标准
1. 测试页可按键（记事本验证）；2. release_all 释放全部；3. 前台窗口检查生效；4. 错误路径不残留按键。

### 测试要求
单元测试用注入参数校验（不真实注入）；实机测试页人工验证。

### 文档要求
用户文档「Windows 测试页」章节。

### 风险
防病毒软件对 SendInput 的误报（记录已知问题）；窗口焦点丢失。

### 完成定义
单元测试全过 + 实机验证通过。

## V1-15 实现紧急停止和全部按键释放

### 背景
安全底线（PRODUCT_PLAN §21 / RISK_AND_COMPLIANCE R2/R10）。

### 问题
紧急停止链路：UI 按钮 + 全局快捷键（V1-21 配合）→ 立即释放全部按键；暂停/停止/崩溃也须释放。

### 目标
`EmergencyStop` 命令贯穿 UI → core → scheduler → backend；按键集合归零断言；native 崩溃（非 Rust panic）与启动自检兑底。

### 用户价值
用户可控的安全感。

### 范围
- emergency_stop IPC + 事件
- 倒计时中可取消
- 暂停/停止/结束/紧急停止的释放语义区分（文档化）
- 崩溃钩子：panic hook + **SetUnhandledExceptionFilter（覆盖访问违规等 native 崩溃，返回 EXCEPTION_CONTINUE_SEARCH 保留 WER）** + 进程退出钩子，均调用 release_all 并写日志
- **启动自检**：会话状态文件标记异常退出 → 启动时对记录的按键集合用 GetAsyncKeyState 核对并按需补抬

### 非目标
看门狗进程（评估后决定）、远程控制。

### 技术建议
- backend 层集中维护「按下集合」，释放幂等；
- 日志记录每次紧急停止的触发源；
- 状态文件含会话 id、异常退出标志、最后按下按键集合（脱敏）。

### 依赖关系
V1-14。

### 验收标准
1. 任意播放状态紧急停止 → 进入 Stopped 终态 + 全部释放（mock 断言）；2. 崩溃钩子被调用（测试模拟 panic 与 SEH 异常）；3. 启动自检对残留按键补抬（mock 验证）；4. 触发源日志。

### 测试要求
紧急停止测试（各状态入口）、幂等释放测试、panic/SEH 钩子测试、启动自检测试（模拟异常退出状态文件）。

### 文档要求
用户文档「紧急停止」章节；PRD §13 同步。

### 风险
崩溃时释放非 100% 可靠；文档明示限制与恢复指引。

### 完成定义
测试全过 + 文档完成。

## V1-21 实现全局快捷键

### 背景
演奏中用户可能无法快速点击 UI（游戏全屏）。

### 问题
全局快捷键注册：开始/暂停、紧急停止；冲突处理与设置页配置。

### 目标
tauri-plugin-global-shortcut 2.3.x（调研已定稿，不手写 RegisterHotKey）集成 + 设置页可改键。

### 用户价值
演奏中免切窗控制。

### 范围
- 默认：紧急停止 **Ctrl+Alt+F9**（避开系统保留组合如 Ctrl+Shift+Esc=任务管理器）；开始/暂停可选
- 注册失败（AlreadyRegistered）提示 + 设置页引导更换；播放期间禁用与演奏按键冲突的组合

### 非目标
复杂和弦快捷键、宏录制。

### 技术建议
- tauri-plugin-global-shortcut 2.3.x（内部隐藏消息窗口 + RegisterHotKey；Windows 修饰键全支持）；
- 默认组合注册失败不得静默——UI 提示并降级（UI 按钮仍可用）。

### 依赖关系
V1-15（设置页承载改键由 V1-28 负责，本 Issue 不依赖设置页）。

### 验收标准
1. 快捷键在游戏前台可用；2. 冲突时提示并可更换（设置页）；3. 设置持久化；4. 默认组合注册失败时明确提示且 UI 兑底可用。

### 测试要求
注册/冲突单元测试（Mock）；实机验证。

### 文档要求
设置页帮助文案。

### 风险
游戏全屏独占键盘；若快捷键失效，紧急停止仍可 UI 触发（兜底）。

### 完成定义
实机验证通过 + 设置持久化。
