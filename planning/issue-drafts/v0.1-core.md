## V1-01 初始化 Tauri 2、Vue 3、Rust Workspace 和 pnpm Workspace

### 背景
v0.1.0 所有功能的承载基础。需要一次性搭好跨平台项目骨架，避免后续重构。

### 问题
从零搭建 Tauri 2 + Vue 3 + TS + Vite + Pinia + Tailwind CSS + shadcn-vue + Rust Cargo Workspace + pnpm workspace，结构需与 ARCHITECTURE.md 一致。

### 目标
可运行的空应用（窗口 + 基础导航），workspace 结构就位，双端构建命令可用。

### 用户价值
开发者体验基础；用户最终获得可安装应用。

### 范围
- `apps/scoreleap/`（Tauri 2 + Vue 3 + Vite + Pinia + Vue Router + Tailwind + shadcn-vue）
- `crates/*` workspace 成员声明（先建 `scoreleap-music-ir` 占位）
- `plugins/tauri-plugin-scoreleap-input` 占位
- 根 `Cargo.toml`、`pnpm-workspace.yaml`、`package.json`、`.gitignore`、`.editorconfig`
- Tauri identifier：`com.superdaobo.scoreleap`

### 非目标
业务功能、测试框架细节（V1-02）、Android 初始化（v0.2）。

### 技术建议
- 用 `pnpm create tauri-app` 或 `cargo create-tauri-app` 脚手架起步，再调整为 workspace 布局；
- Tauri 2 固定版本（Cargo.lock 提交）；
- 前端包管理器统一 pnpm。

### 依赖关系
无（根任务）。

### 验收标准
1. `pnpm dev` 可启动窗口；2. `cargo build` 通过；3. workspace 结构符合 ARCHITECTURE.md 附录 B；4. identifier/namespace 正确。

### 测试要求
`cargo test` 与 `pnpm test`（占位）通过。

### 文档要求
更新 README 开发章节（如何安装依赖、运行 dev）。

### 风险
脚手架版本漂移；Windows 需要 WebView2（打包时处理）。

### 完成定义
验收标准全过 + PR 审查通过 + CI 绿。

## V1-03 定义 Music IR

### 背景
所有输入格式的统一中间表示（ADR-0003）。

### 问题
`scoreleap-music-ir` crate 不存在；类型与时间语义未落地。

### 目标
发布 `MusicDocument`/`Track`/`NoteEvent`/`TempoEvent`/`TimeSignatureEvent`，整数微秒时间，serde 序列化，单元测试。

### 用户价值
无直接用户价值；一切功能的地基。

### 范围
- 类型定义（ARCHITECTURE.md 附录 A）
- `duration_us` 语义、事件排序不变量（解析器保证有序）
- 辅助方法：总时长计算、音符区间查询（预览用）

### 非目标
解析逻辑（V1-04）、编排（V1-07~V1-10）、编辑能力（v0.3）。

### 技术建议
- `i64` 微秒；`us_per_quarter: u32`；
- serde derive + `#[serde(deny_unknown_fields)]` 评估；
- 公共类型由 Agent A 管理，变更需 ADR。

### 依赖关系
V1-01。

### 验收标准
1. 类型可序列化/反序列化往返一致；2. 时间单位全部显式微秒；3. 空文档合法；4. 不变量文档化。

### 测试要求
构造/序列化/边界（负值拒绝、超大值溢出检查）测试。

### 文档要求
ARCHITECTURE.md 附录 A 同步更新。

### 风险
类型设计过早固化；预留 v0.3 编辑扩展位（如 `id` 字段评估）。

### 完成定义
类型稳定 + 测试全过 + 文档同步。

## V1-04 实现 MIDI 解析和 Tempo Map

### 背景
.vim/.midi 是 v0.1 唯一输入格式。

### 问题
用 midly 解析 SMF（格式 0/1/2），处理 running status、velocity=0、SMPTE division、多 tempo 变化，产出 Music IR。

### 目标
`scoreleap-midi::parse(bytes) -> Result<MusicDocument>`：轨道、TempoEvent 有序数组、TimeSignatureEvent、NoteEvent 绝对微秒时间。

### 用户价值
用户能导入自己的 MIDI 曲谱。

### 范围
- midly 集成（版本锁定）
- ticks → 微秒分段换算（ADR-0003 公式）
- 轨道名（track name 元事件）、乐器名（评估）
- 错误分类：坏文件/不支持特性/超限

### 非目标
MIDI 导出、格式 2 的完整多轨语义（仅尽力兼容读取，不在 v0.1 验收范围）、MusicXML。

### 技术建议
- midly 的事件迭代器 + 手动 tempo 累加；
- 注意：midly 不自动处理 running status（SMF 规范要求实现者处理）——验证 midly 行为，必要时自行处理；
- velocity=0 视作 NoteOff 的标准语义必须测试覆盖。

### 依赖关系
V1-03。

### 验收标准
1. 格式 0/1 正确解析；2. tempo 变化正确（黄金样例断言）；3. velocity=0 与显式 NoteOff 等价；4. running status 文件正确；5. SMPTE division 正确转换或明确报错；6. 解析错误信息可读。

### 测试要求
fixtures/midi 黄金样例（V1-22 配合）；Running Status 测试；Note On velocity 0 测试；多轨合并测试；损坏文件测试。

### 文档要求
crate 文档 + ARCHITECTURE.md §4 更新。

### 风险
SMPTE division 罕见但需处理；超大文件内存（上限 50MB 先拒）。

### 完成定义
黄金样例全过 + 错误路径测试全过。

## V1-05 定义 Game Profile Schema

### 背景
Game Profile 是「不绑定单一游戏」的关键抽象（ADR-0004）。

### 问题
profile.json / windows-keymap.json / android-layout.json 的 schema 与加载校验未定义。

### 目标
`scoreleap-game-profile` crate：`GameProfile` 类型、serde schema、校验逻辑、加载 API。

### 用户价值
无直接价值；决定新游戏适配成本。

### 范围
- `GameProfile`/`InstrumentLayout`/`KeySlot` 类型
- 校验：键数一致性、音域合法（midi_low ≤ midi_high）、映射唯一性、坐标 [0,1] 范围
- `ProfileStore`：从目录加载 + 缓存

### 非目标
Windows 扫描码具体映射（V1-06/V1-14）、Android 布局验证（v0.2）、远程 profile。

### 技术建议
serde + thiserror；`version` 字段预留迁移；profile 目录约定 `game-profiles/<id>/`。

### 依赖关系
V1-01。

### 验收标准
1. schema 可校验合法/非法 profile；2. 错误信息包含字段路径；3. 加载 API 返回结构化错误；4. 默认无 profile 时行为明确（提示导入）。

### 测试要求
Schema 测试（合法/缺字段/越界/重复映射）；JSON fixture。

### 文档要求
ARCHITECTURE.md §10 与 ADR-0004 同步。

### 风险
schema 冻结过早；用 `version` + 宽松解析缓解。

### 完成定义
校验测试全过 + 文档同步。

## V1-07 实现自动转调

### 背景
MIDI 音域常超出 36 键乐器范围，需要自动适配。

### 问题
`scoreleap-arranger` 的转调模块：给定 Profile 音域与音符分布，计算最优移调量（尽量保留音符，优先不损失旋律）。

### 目标
`AutoFitTranspose` 算法 + `transpose_semitones` 应用 + 结果摘要（移调量、保留率）。

### 用户价值
一键让曲子适配乐器。

### 范围
- 移调 ±24 半音搜索，评分函数（音符落在音域内数量/权重）
- 手动移调参数应用（与自动互补）

### 非目标
多调性检测、微调音、非十二平均律。

### 技术建议
简单评分即可（v0.1）；算法在纯函数中实现便于测试。

### 依赖关系
V1-03。

### 验收标准
1. 自动移调量正确（黄金样例）；2. 手动移调 ±24 边界；3. 移调后音符越界由 V1-08 处理（不重叠责任）。

### 测试要求
转调测试：正/负移调、边界、空轨道。

### 文档要求
参数页文案说明（PRD §4.4 同步）。

### 风险
评分函数主观；先用可解释的简单规则。

### 完成定义
算法测试全过 + 参数接入（V1-18 后整体验证）。

## V1-08 实现音域折叠

### 背景
移调后仍有音符超出乐器音域。

### 问题
折叠策略：降八度/丢弃/静音，需与复音限制协同。

### 目标
`RangeStrategy` 实现 + 越界统计。

### 用户价值
不合理的音符不再破坏演奏。

### 范围
- 策略：OctaveDown（最多折叠 N 次后丢弃）、Drop、Mute
- 折叠后仍越界 → 按策略兜底

### 非目标
智能旋律保留（v0.3 评估）、按轨道差异化策略（先全局）。

### 技术建议
纯函数；输出统计（折叠数/丢弃数）供 UI 提示。

### 依赖关系
V1-03。

### 验收标准
1. 三种策略行为正确；2. 折叠链不无限循环；3. 统计正确。

### 测试要求
音域折叠测试：边界音符、多八度折叠、丢弃统计。

### 文档要求
参数页说明各策略含义。

### 风险
折叠导致旋律混乱；默认策略文档化。

### 完成定义
策略测试全过。

## V1-10 实现和弦简化

### 问题

### 目标
`simplify` 实现：滑动窗口内音符数 > max_polyphony 时裁剪，输出被裁剪统计。

### 用户价值
和弦不再丢失整体听感。

### 范围
- 策略：保留最高力度/最后开始/最低音的组合规则（可配置）

### 非目标
和弦识别（音程分析）、声部进行优化。

### 技术建议
时间窗口扫描（音符起点排序）；纯函数。

### 依赖关系
V1-03。

### 验收标准
1. 超限裁剪正确；2. 不超限不裁剪；3. 旋律轨道优先权（可配）。

### 测试要求
和弦裁剪测试：同时发声窗口、优先级、边界。

### 文档要求
参数页说明简化策略。

### 风险

### 完成定义
测试全过。

## V1-12 实现精确 Scheduler

### 背景
演奏核心：按微秒时间轴精确触发按键（ADR-0005）。

### 问题
`scoreleap-scheduler`：Clock 抽象、命令通道、虚拟时钟、暂停/恢复/停止/紧急停止状态机、InputBackend trait。

### 目标
调度核心 + `MockInputBackend` + `VirtualClock` + 完整状态机测试。

### 用户价值
可靠演奏（不漂移、可停）。

### 范围
- `Clock`/`SystemClock`/`VirtualClock`
- 状态机：Idle/Countdown/Playing/Paused/Stopped/Finished
- 命令通道（std mpsc）+ 调度线程
- 暂停释放按键、恢复重建持续音符
- 速度缩放（0.5x–2.0x）
- `InputBackend` trait + `MockInputBackend`

### 非目标
真实 Windows 注入（V1-14）、真实时钟精度调优（V1-13 后）、Android 手势（v0.2）。

### 技术建议
- 不依赖 tokio（std 线程 + channel，评估结论回填）；
- 紧急停止为最高优先级命令；
- 精度测量在 V1-13 处理，本 Issue 保证语义正确。

### 依赖关系
V1-11。

### 验收标准
1. 虚拟时钟下序列精确触发；2. 暂停无残留按键（mock 断言）；3. 恢复重建按下态；4. 紧急停止清空队列并 release_all；5. 速度缩放时间正确；6. 结束后全部释放。

### 测试要求
Scheduler 虚拟时钟测试、暂停恢复测试、紧急停止测试、速度测试。

### 文档要求
ARCHITECTURE.md §9 同步。

### 风险
线程同步竞态；用通道 + 单一调度线程规避。

### 完成定义
状态机与调度测试全过。
