## V1-22 建立黄金 MIDI 测试样例

### 背景
解析与编排的正确性需要可回归的基准（ADR-0003 微秒断言）。

### 问题
fixtures/midi 与 fixtures/sequences 缺失；需要覆盖 tempo 变化、running status、velocity=0、多轨、重复音、和弦、音域越界等场景。

### 目标
黄金样例集：输入 MIDI + 期望 Music IR/CompiledSequence（JSON），测试脚本比对。

### 用户价值
工程质量保障，防回归。

### 范围
- fixtures/midi/：≥8 个样例（单轨/多轨/变速/running status/velocity0/SMPTE/重复音/长曲）
- fixtures/sequences/：期望输出
- fixtures/profiles/：测试 profile
- 生成工具（scripts/）与说明

### 非目标
真实版权曲目（用程序生成或公有领域素材）、音频样例。

### 技术建议
- 样例用脚本生成（确定性）；来源与生成方式记录在 README；
- 期望输出由实现验证后人工复核冻结。

### 依赖关系
V1-04。

### 验收标准
1. 每个样例有输入+期望输出+说明；2. 断言脚本可运行；3. 样例不含版权曲目。

### 测试要求
断言脚本在 CI 运行（并入 V1-23）。

### 文档要求
fixtures/README。

### 风险
期望值人工出错；双人复核。

### 完成定义
样例集 + 断言脚本入库。

## V1-23 建立单元测试和集成测试

### 背景
质量门槛落地（测试架构见 ARCHITECTURE.md §15）。

### 问题
Rust 单元/集成测试与前端测试矩阵未建立；调度测试依赖虚拟时钟。

### 目标
覆盖：Music IR、Tempo Map、Running Status、velocity=0、多轨合并、转调、音域折叠、和弦裁剪、重复音、Scheduler（虚拟时钟）、暂停恢复、紧急停止、Profile Schema、导入错误文件、前端状态。

### 用户价值
每次变更可验证。

### 范围
- Rust：各 crate 单元测试 + crates 间集成测试（黄金样例）
- 前端：Vitest（stores/参数校验/错误映射）
- 覆盖度量（cargo-llvm-cov 评估，非门槛）

### 非目标
Playwright e2e 全量（随 UI Issue 渐进）、真实按键注入测试。

### 技术建议
- Scheduler 测试只允许 VirtualClock + MockInputBackend；
- Bug 修复必须附带回归测试（CONTRIBUTING）。

### 依赖关系
V1-12、V1-22。

### 验收标准
1. 所有测试类别存在且通过；2. 无 flaky 测试（CI 连跑 3 次稳定）；3. 覆盖率报告产出（记录基线）。

### 测试要求
即本 Issue 本身；`cargo test --workspace` + `pnpm test` 全绿。

### 文档要求
测试说明（如何跑、如何加样例）。

### 风险
测试耗时增长；分 crate 限时。

### 完成定义
测试矩阵全绿 + 基线覆盖率记录。

## V1-24 建立 GitHub Actions

### 背景
CI 是合并门槛（CONTRIBUTING 质量门槛）。

### 问题
ci.yml（前端 typecheck/test、Rust fmt/clippy/test、构建验证）未建立。

### 目标
PR 触发 CI 全绿；先稳定后优化（缓存/矩阵后续）。

### 用户价值
协作安全网。

### 范围
- ci.yml：pnpm install → typecheck → lint → test → build；cargo fmt --check → clippy（workspace, all-targets, all-features）→ test --workspace
- 依赖缓存（actions/cache 评估后加）

### 非目标
Windows 安装包构建（V1-25）、Android CI（v0.2）、release 自动化（后续）。

### 技术建议
- Windows runner 即可（本版本仅 Windows）；
- 超时与重试策略。

### 依赖关系
V1-02。

### 验收标准
1. PR 触发全部检查；2. 故意引入 fmt 错误能被拦截（验证）；3. 运行时间可接受（<15min）。

### 测试要求
CI 本身即验证。

### 文档要求
CI 状态徽章（README）。

### 风险
Windows runner 工具链版本漂移；锁版本。

### 完成定义
CI 全绿 + 拦截验证通过。

## V1-25 构建 Windows 安装包

### 背景
用户需要可安装产物。

### 问题
Tauri Windows 构建：NSIS 安装包、版本一致性（package.json/Cargo.toml/tauri.conf）、产物上传。

### 目标
`pnpm tauri build` 产出 NSIS 安装包；workflow 上传 artifact；无证书 SmartScreen 风险记录。

### 用户价值
可安装使用。

### 范围
- tauri.conf.json 完善（identifier/窗口/图标/bundle 配置）
- windows-build.yml：构建 + artifact 上传
- 版本一致性检查脚本（scripts/check-version）

### 非目标
代码签名证书（记录为后续）、自动发布 Release（V1-27 手工触发评估）、增量更新。

### 技术建议
- 图标资源齐全（Windows .ico）；
- 安装包命名带版本号。

### 依赖关系
V1-24。

### 验收标准
1. 本机构建成功且可安装运行；2. CI artifact 产出；3. 版本一致性脚本通过。

### 测试要求
安装 → 启动 → 导入 → 演奏冒烟（人工）。

### 文档要求
安装说明（含 SmartScreen 提示）。

### 风险
WebView2 依赖（安装包处理）；杀软误报（记录）。

### 完成定义
安装包产出 + 冒烟通过。

## V1-26 编写用户文档

### 验收标准

### 测试要求

### 文档要求
即本 Issue。

### 风险
